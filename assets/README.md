# assets\ — невосстановимые исходники, и они версионируются

Здесь лежит то, что **нельзя пересобрать по рецепту**: файлы `.blend` со скульптом,
вылепленная руками геометрия, готовые `.esp`, авторские текстуры.

Раньше эта папка была исключена из git с припиской «двоичное не кладём, но и терять нельзя».
Так делать было неправильно: журнал сборки описывает, **как** превратить исходник в конечный
файл, но сам по себе он бесполезен, если исходника нет. Теперь папка версионируется через
**Git LFS**: git хранит указатель в несколько строк, файл лежит в хранилище LFS рядом.

---

## Что сюда кладётся, а что нет

Правило — **скорость изменения**, а не размер. LFS не сжимает версии друг относительно
друга: каждая правка кладётся целиком. Поэтому:

| кладётся | почему |
|---|---|
| скульпт `.blend`, вылепленная геометрия | рецептом не выражается, потеря невосстановима |
| готовые `.esp` | собраны руками, меняются редко |
| донорские меши, на которых стоит мод | меняются никогда; без них журнал не исполнить |

| не кладётся | почему |
|---|---|
| результат каждой сборки | 46 МБ за прогон, а экспорт NIF не повторяется побайтово — каждая сборка дала бы новый слепок при той же геометрии |
| распакованные архивы, `work\` | восстанавливаются из `downloads\` |
| выпуски мода | их хранит архив в `downloads\` и страница на Nexus |

Именно ради второй таблицы и написан журнал: он заменяет хранение промежуточного.

---

## Права: репозиторий с донорами обязан быть закрытым

Донорские меши — чужие. Elegant разрешает использовать модели **в моде**; выкладывание
самого файла в открытый репозиторий — это раздача чужого ассета, а не использование.
То же у XP32.

Отсюда жёсткое следствие: **как только донор попал в историю, репозиторий не может стать
открытым.** Убрать файл из истории задним числом — это переписывание всей истории, и на
клонах у других оно не сработает. Решение принимается **до** первой отправки на сервер,
а не после.

Если когда-нибудь понадобится открытая витрина — это отдельный репозиторий с одними
рецептами, без `assets\`.

---

## Пока нет удалённого сервера, это версии, но ещё не резервная копия

Объекты LFS лежат в `.git\lfs\objects` на том же диске. История появляется сразу,
а страховка от смерти диска — только после `git push` на закрытый сервер.
