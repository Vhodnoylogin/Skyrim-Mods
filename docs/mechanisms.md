# Два механизма изменения тела, которые легко спутать

## Вес: `_0` и `_1`

Движок держит два целых меша и линейно тянет вершины между ними по полю «вес» персонажа.
Один параметр на всё тело, SKSE не нужен.

`_0` и `_1` — это **одно и то же тело при весе 0 и при весе 100**, а не «минимум и максимум
набора ползунков». Собранная по второму пониманию пара даёт уродство: раздутые кисти и стопы
при тонких предплечьях.

Насколько сильно вес меняет фигуру в самой игре — замерено по парам, которые лежат в сборке:

| область | HIMBO | CBBE |
|---|---|---|
| таз | +1.4 % | +2.6 % |
| грудная клетка | +1.1 % | +1.8 % |
| плечо | +7.1 % | +0.7 % |
| бедро | 0.0 % | +1.0 % |
| кисти, стопы, уши, хвост | не меняются | не меняются |

То есть вес — скромная поправка на массу, единицы процентов.

В ванильной записи `ARMA 000CDD87` (`NakedTorsoWerewolfBeast`) ползунок веса **выключен**,
и файл `_0` движок не читает никогда:

    ваниль   DNAM = 00 00 00 00 02 00 00 17 00 00 00 00
    включён  DNAM = 00 00 02 02 02 00 00 17 00 00 00 00

Там же женская модель указывает на **мужской** меш — поэтому самки-вервольфы в ванили выглядят
самцами. Оба поля чинятся одной перезаписью записи.

## Именованные морфы: файл `.tri`

Одна модель плюс файл поимённых сдвигов. Значения задаются на ходу вызовом
`NiOverride.SetBodyMorph`, ползунков может быть сколько угодно и они независимы. На этом
механизме стоит OBody.

Устройство обязано повторять человеческое, иначе не работает:

    malebodywerewolf_0.nif  -> метка BODYTRI -> actors\werewolfbeast\character assets\malebodywerewolf.tri
    malebodywerewolf_1.nif  -> метка BODYTRI -> тот же путь, дословно

Имя файла морфов **без суффикса веса**, путь **относительно `meshes\`**, и оба тела ссылаются
на один файл. Абсолютный путь в метке приводит к тому, что движок ищет
`meshes\D:\...` и молча не находит ничего.

PyNifly пишет в метку `truncate_filename(trippath, "meshes")` — обрезает путь по слову `meshes`.
Поэтому экспортировать надо **в дерево, где такая папка есть**, а оба тела — в одну папку под
одним именем, с переименованием уже после экспорта.

Ключ формы с именем, начинающимся на `>`, уходит в файл морфов BodySlide.

## Что из этого проверено

- Вес на вервольфе работает — доказано прогоном.
- Именованные морфы — проверка собрана, прогон не завершён.
