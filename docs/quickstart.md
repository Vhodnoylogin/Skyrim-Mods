# morphbench: с чего начать

Записка для того, кто будет пользоваться верстаком, а не дописывать его. Устройство и правила
границы — в [README.md](../README.md).

## Что нужно

- Python 3.12 с пакетами `numpy` и `pillow` (без `pillow` нет растеризатора PNG).
- Аддон **PyNifly** в каталоге аддонов Blender: `%APPDATA%\Blender Foundation\Blender\<версия>\scripts\addons\io_scene_nifly`.
  Программа находит его сама; если он лежит в другом месте, путь задаётся ключом `pynifly`
  в `morphbench.json`. Своих разборщиков NIF и TRI у верстака нет и быть не должно.

## Запуск

Все команды идут из папки модуля:

    python mb.py <команда> <меш.nif> [ключи]

Файл морфов `.tri` подбирается рядом с мешем сам (то же имя без суффикса веса `_0`/`_1`);
явно — ключом `--tri`. Ко всякой команде подходит `--json`: тот же ответ машинно.

| Команда | Что отвечает |
|---|---|
| `summary`, `shapes`, `bones`, `morphs`, `empty` | что за меш, его части, кости, ползунки и пустые морфы |
| `missing <nif> A B C` | каких ожидаемых ползунков в файле нет |
| `strain <nif> [--morph X]` | где морф растягивает или рвёт поверхность |
| `layers <nif> --morph X [--adjacent] [--base S]` | следуют ли оболочки за кожей; `--adjacent` оставляет только те, что обязаны |
| `binding <nif> --morph X [--shape S]` | каким костям принадлежит то, что морф двигает, и какие кости брошены |
| `focus <nif> --bone B \| --morph X \| --shape S` | наведение камеры числами: центр и радиус |
| `colliders <nif> --skeleton S.nif [--find B] [--clearance]` | невидимые капсулы столкновений: где стоят и как сидят по коже |
| `fit <nif> --skeleton S.nif [--find B] [--save новый.nif] [--ppb]` | посадить капсулы по коже при нынешних ползунках |
| `render <nif> --out кадр.png [...]` | кадр PNG |
| `sheet <nif> --out папка [...]` | несколько ракурсов подряд |
| `web <nif> --out страница.html [...]` | самодостаточная смотрелка в браузере, один файл |
| `env` | под MO2 ли запущены, какие игры видны, какой корень обзора по умолчанию |
| `catalog [папка] [--all] [--find X]` | обзор мешей под папкой с подобранными файлами морфов |
| `serve [--root папка] [--port N] [--nif X]` | страница со списком мешей на локальном порту: тело выбирается в ней |

Общие ключи `render`, `sheet` и `web`:

    --view front|side|back|top|below|quarter    ракурс из настроек
    --look 40,15                                произвольный ракурс: поворот,подъём
    --colour bone|morph|strain --morph X        раскраска: по костям, по сдвигу морфа, по растяжению
    --slider X=1                                значение ползунка; ключ повторяем
    --only body,head                            какие части показывать
    --zoom 2   --pan=5,-3   --size 900x900      масштаб, панорама, размер кадра
    --zoom-at=2,0.4,-0.3                        масштаб к точке: новый масштаб и точка в долях
                                                половины меньшей стороны кадра от центра (вправо, вверх)
    --light camera|world                        свет за камерой или отдельно от неё
    --light-dir=0.35,0.45,0.82                  направление на источник: в осях камеры (вправо, вверх,
                                                к зрителю) при свете за камерой, иначе мировое
    --light-power=0.35,0.65,0.15                силы: рассеянная, направленная, встречная подсветка
    --focus-bone "L Finger" | --focus-morph X | --focus-shape head    смотреть на часть тела
    --skeleton skeleton.nif --colliders [--bumper]   слой капсул столкновений поверх тела

Пары чисел с минусом впереди пишутся через знак равенства: `--pan=-5,3`, `--look=-10,5`.
Подстрока в `--focus-bone` объединяет все подходящие кости: `L Finger` — все пальцы левой лапы.

## Капсулы столкновений

Удары и прикосновения игра считает не по коже, а по невидимым капсулам, которые лежат
**в файле скелета** — по одной на кость. Посмотреть на них поверх тела:

    python mb.py render тело.nif --skeleton skeleton.nif --colliders --view side --out кадр.png

Капсулы ложатся полупрозрачно: внутри тела просвечивают сквозь кожу, снаружи — сразу видны
на фоне. Цилиндр перемещения по умолчанию скрыт, он вчетверо больше тела: `--bumper` включает.

Насколько они расходятся с телом — числами:

    python mb.py colliders тело.nif --skeleton skeleton.nif --clearance

`снаружи 62% кожи, дальше всего 14.0` читается так: почти две трети кожи этой части лежат вне
капсулы, и в самом плохом месте рука пройдёт четырнадцать единиц, ничего не задев.

Посадить капсулы по коже — при тех ползунках, что заданы:

    python mb.py fit тело.nif --skeleton skeleton.nif --slider CLAWTorsoGirth=0.5         --save новый-skeleton.nif --ppb

Садится по тому, что видно: `--only body` — по коже, без ключа — по силуэту вместе с шерстью.
`--save` пишет новый файл скелета (всегда новый: исходный принадлежит чужому моду), `--ppb`
выдаёт строки для `PPB_tuning.txt`, который Precision Physic Bodies перечитывает примерно раз
в секунду прямо во время игры.

## Свет

По умолчанию источник едет вместе с камерой: что видно, то и освещено, и все шесть ракурсов
одинаково читаемы. `--light world` (или галочка «за камерой» на странице) возвращает
неподвижный источник с мировым направлением `lightDirection` из настроек. Затенение мягкое,
по нормали вершины; `shading: "flat"` в настройках даёт плоскую заливку по треугольникам.
Встречная подсветка (`fill`) слегка освещает теневую сторону, чтобы форма не пропадала.

## Выбор модели и запуск под Mod Organizer 2

`mb.py catalog <папка>` перечисляет все меши под папкой, к которым подобран файл морфов (`--all`
даёт и остальные); `mb.py serve --root <папка>` поднимает страницу, где тело выбирается
из списка без перезапуска, а другую папку можно назвать прямо на странице.

Под MO2 моды слиты в один `Data` игры, и именно там лежат меши всей сборки. Утилита узнаёт,
что запущена через MO2 (в процесс загружена библиотека usvfs), берёт `Data` игры из реестра
и делает его корнем обзора; выйти за его пределы не даст. Чтобы так запускать:

1. В MO2: список исполняемых файлов (кнопка с шестерёнкой) → добавить запись.
2. **Binary**: `python.exe`. **Arguments**: `"<путь к dev\morphbench>\mb.py" serve`.
   **Start in**: папка `dev\morphbench`.
3. Запустить эту запись из MO2. Проверка: такая же запись с аргументом `env` вместо `serve`
   (или временно поправленные аргументы той же записи) должна ответить «под MO2: да»
   и назвать `Data` игры корнем обзора.

Вне MO2 корень обзора надо назвать самому (`--root` или `catalogRoot` в настройках):
умолчания у него нет, и это намеренно.

## Настройки

`morphbench.json` рядом с `mb.py` создаётся при первом запуске; ключи, которых в старом файле
нет, дописываются сами. Что там менять чаще всего:

| Ключ | Смысл | По умолчанию |
|---|---|---|
| `baseShape` | имя базовой части — кожи, за которой следуют оболочки | `body` |
| `contactRadius` | в каком радиусе от кожи вершина оболочки считается лежащей над ней | 6 |
| `minContact` | доля вершин над сдвинутой кожей, с которой оболочка обязана следовать | 0.02 |
| `strainThreshold` | растяжение ребра, с которого оно считается разорванным | 0.25 |
| `views` | ракурсы: имя → поворот и подъём в градусах | шесть штук |
| `focusPadding` | запас вокруг цели наведения в долях её радиуса | 1.25 |
| `lightFollowCamera` | свет едет с камерой | `true` |
| `lightCameraDirection` / `lightDirection` | направление на источник в осях камеры / мировое | `[0.35, 0.45, 0.82]` / `[-0.4, -0.7, 0.6]` |
| `ambient`, `diffuse`, `fill` | силы света: рассеянная, направленная, встречная | 0.35, 0.65, 0.15 |
| `shading` | `smooth` по нормали вершины или `flat` по треугольнику | `smooth` |
| `catalogRoot`, `catalogSubdirs` | корень обзора вне MO2 и подпапки, где искать | пусто, `["meshes"]` |
| `serveHost`, `servePort` | адрес и порт страницы со списком | `127.0.0.1`, 8767 |

## На что смотреть в ответах

- **`layers`.** «Доля» — амплитуда оболочки к амплитуде кожи. «Над сдвигом» — какая часть
  оболочки лежит над сдвигаемой кожей; «смежна» — обязана ли она следовать вообще;
  «должна на» — насколько сдвинута кожа прямо под ней. Оболочка, которая смежна и не следует, —
  это разрыв слоёв.
- **Оболочка может лежать не на коже, а над другой оболочкой** (заплатка шва над шерстью,
  шерсть морды над головой). Тогда смежность с кожей будет нулевой, и спрашивать надо
  относительно её настоящей подложки: `--base fur_belly`, `--base head`.
- **`binding`.** Кости, «сдвинутые лишь частично», — место, где морф двигает одну часть
  кости и бросает другую; там поверхность растягивается, как перчатка на лапе.
- **`empty` и `missing`** ловят молчащие поломки: ползунок есть в файле и не двигает ничего,
  или его нет вовсе, хотя рецепт его обещал.

## Страница в браузере

`mb.py web` собирает один HTML-файл без обращений наружу: открывается с диска, тело
вращается левой кнопкой, колесо — масштаб к точке под курсором, правая кнопка — панорама,
двойной щелчок — сброс. `mb.py serve` даёт ту же страницу с выбором тела из списка.
Внизу панели — состояние показа тем же JSON, что даёт `--json`, и команда `mb.py render`,
которой этот же кадр получается без окна: всё, что нажато мышью, можно повторить в скрипте.

## Проверки

    python tests\run.py

Фигуры для проверок собираются в памяти, файлов сборки они не трогают; наборы, которым нужен
PyNifly для записи настоящих TRIP и NIF, без него пропускаются с причиной.
