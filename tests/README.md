# Проверки

```
python tests/run.py                 все наборы подряд, итог одной строкой
python tests/run.py test_tri.py     один набор по шаблону имени
python tests/test_layers.py         любой файл запускается и сам по себе
```

Только `unittest` из стандартной библиотеки. Проверки лежат **вне** пакета `morphbench\`
и не импортируются им; корень программы они находят от своего расположения.

Ни один набор не читает файлов сборки: тело собирается в памяти из `Shape`, `Bone`,
`BodyModel`, `Morph`, `MorphSet` (общие сборщики — в `common.py`) и подключается к фасаду
через `MorphBench.attach`. Настройки создаются во временной папке
(`Config(<tmp>/morphbench.json)`), настоящий `morphbench.json` не трогается.

| Набор | Нужен PyNifly | Что проверяет |
|---|---|---|
| `test_tri.py` | да | настоящий TRIP, записанный `TripFile`, читается `MorphSet.from_file` с точностью кванта int16; FRTRI, записанный `TriFile` |
| `test_morphs.py` | нет | пустой морф, объявленный-но-отсутствующий, `apply` с долей и с номерами за пределами меша |
| `test_strain.py` | нет | растяжение рёбер на сетке из двух треугольников, посчитанное вручную; порог; сдвиг целиком даёт ноль |
| `test_layers.py` | нет | смежность оболочек над сдвигаемой и несдвигаемой кожей; `Proximity`; `contactRadius` и `minContact` из настроек |
| `test_facade.py` | нет | таблицы фасада совпадают с `as_dict()` объектов `Analyzer`; JSON без numpy; ползунки = `Morph.apply`; признаки раскраски |
| `test_focus.py` | частично | `sphere_of`, наведение на кость/морф/часть, `framing`, `focus_targets`; одна проверка `open()` пишет NIF |
| `test_nif.py` | да | крошечный NIF, созданный PyNifly, читается `BodyModel.from_nif`; `open()` находит `.tri` рядом |
| `test_web.py` | нет | страница `presenters.web` из бенча в памяти: `<canvas`, имена, без внешних ссылок; пропуск, пока модуля нет |
| `test_text.py` | нет | таблица и сводка слоя `presenters.text` |

PyNifly ищется тем же путём, что и в программе: ключ `pynifly` в настройках, иначе аддон
`io_scene_nifly` в каталоге аддонов Blender. Без него наборы, которым нужно записать
настоящий файл, **пропускаются** с причиной — пропуск не считается сбоем. Отказ самого
API PyNifly при создании файла тоже даёт пропуск с текстом исключения: проверяется чтение
верстака, а не PyNifly.
