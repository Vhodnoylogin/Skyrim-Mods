# Проверки

```
python tests/run.py                 все наборы подряд, итог одной строкой
python tests/run.py test_tri.py     один набор по шаблону имени
python tests/test_layers.py         любой файл запускается и сам по себе
```

Только `unittest` из стандартной библиотеки. Проверки лежат **вне** пакета `morphbench\`
и не импортируются им; корень программы они находят от своего расположения.

Ни один набор не читает файлов сборки: тело собирается в памяти из `Shape`, `Bone`,
`BodyModel`, `Morph`, `MorphSet` (общие сборщики — в `common.py`, замкнутый куб с обходом
наружу — в `solids.py`) и подключается к фасаду через `MorphBench.attach`. Настройки
создаются во временной папке (`Config(<tmp>/morphbench.json)`), настоящий `morphbench.json`
не трогается; `mb.py` в проверках получает фасад с такими же настройками через подмену
`mb.MorphBench`. Запуск под MO2 имитируется подменой `Environment.inside_mo2`, игры из
реестра — подменой `Environment.game_roots`: ни одной настоящей папки сборки.

| Набор | Нужен PyNifly | Что проверяет |
|---|---|---|
| `test_tri.py` | да | настоящий TRIP, записанный `TripFile`, читается `MorphSet.from_file` с точностью кванта int16; FRTRI, записанный `TriFile` |
| `test_morphs.py` | нет | пустой морф, объявленный-но-отсутствующий, `apply` с долей и с номерами за пределами меша |
| `test_strain.py` | нет | растяжение рёбер на сетке из двух треугольников, посчитанное вручную; порог; сдвиг целиком даёт ноль |
| `test_layers.py` | нет | смежность оболочек над сдвигаемой и несдвигаемой кожей; `Proximity`; `contactRadius` и `minContact` из настроек |
| `test_facade.py` | нет | таблицы фасада совпадают с `as_dict()` объектов `Analyzer`; JSON без numpy; ползунки = `Morph.apply`; признаки раскраски |
| `test_focus.py` | частично | `sphere_of`, наведение на кость/морф/часть, `framing`, `focus_targets`; одна проверка `open()` пишет NIF |
| `test_framing.py` | нет | `MorphBench.framing()`: центр и полуразмах в осях камеры (yaw 0 и 90 вручную), только видимые части, ползунки, наведение × `focusPadding`, панорама, часть без треугольников не в счёт, всё скрыто — `RuntimeError` |
| `test_normals.py` | нет | `vertex_normals`: сетка против часовой — вверх, обратный обход — вниз, куб — наружу, одинокая вершина — (0,0,1), единичная длина, вес по площади; фасад считает по деформированным вершинам |
| `test_light.py` | нет | свет `ViewState`: режим из настроек, вектор едет с камерой либо стоит в мире, направление в текущий режим, нулевой вектор, зажим сил, `light_state` без numpy; растеризатор на кубе: перед и зад одинаково ярки при свете за камерой и по-разному при мировом, `fill` подсвечивает тень, `flat` красит грань одним цветом |
| `test_zoom.py` | нет | `zoom_at`: точка сцены под курсором остаётся на месте по формулам растеризатора (до 1e-3 px, холст не квадратный), зажим ниже 0.05, без кадра меняется только масштаб, фасад считает кадр сам |
| `test_catalog.py` | частично | `Catalog` на дереве пустых файлов: суффиксы веса, регистр, формат по заголовку, подпапки, `get` по номеру/имени/подстроке, кеш и `rescan`; `Environment` под имитацией MO2 и игр; фасад `catalog`/`open_entry` (настоящий NIF — одна проверка) |
| `test_cli.py` | частично | `mb.py env --json`, `catalog --json/--all/--find`; `render` с `--zoom-at`, `--light`, `--light-dir`, `--light-power` на настоящем NIF |
| `test_serve.py` | да | `presenters.serve`: сервер фоновым потоком на порту 0, `/api/environment`, `/api/catalog`, `/api/payload`, страница с холстом, коды 400/403/404 с JSON, 403 под имитацией MO2, `stop()` освобождает порт; пропуск, пока модуля нет |
| `test_nif.py` | да | крошечный NIF, созданный PyNifly, читается `BodyModel.from_nif`; `open()` находит `.tri` рядом |
| `test_web.py` | нет | страница `presenters.web` из бенча в памяти: `<canvas`, имена, без внешних ссылок; пропуск, пока модуля нет |
| `test_text.py` | нет | таблица и сводка слоя `presenters.text` |

PyNifly ищется тем же путём, что и в программе: ключ `pynifly` в настройках, иначе аддон
`io_scene_nifly` в каталоге аддонов Blender. Без него наборы, которым нужно записать
настоящий файл, **пропускаются** с причиной — пропуск не считается сбоем. Отказ самого
API PyNifly при создании файла тоже даёт пропуск с текстом исключения: проверяется чтение
верстака, а не PyNifly.
