# dev - ветвь разработки

Один репозиторий, **ветка на каждую разработку**. На стволе `master` лежит **готовое**:
общие правила игнорирования, это описание и те модули, которые доведены до конца. Разработка
идёт не там, а на ветках.

Каждый модуль живёт на своей ветке, постоянно выписанной в собственную рабочую копию:

| Папка | Ветка | Что это |
|---|---|---|
| `dev\repo\` | `master` | ствол, здесь физически лежит `.git` |
| `dev\envoy\` | `envoy` | Envoy Framework: мост и два тестовых модуля рядом с ним |
| `dev\voice\` | `voice` | голосовая служба: распознавание и синтез речи |
| `dev\wt-mo2aibridge\` | `mo2aibridge` | плагин MO2 AI Bridge |
| `dev\wt\<задача>\` | временная | ветка под одну задачу внутри модуля |

Такая раскладка даёт главное: в один коммит **не могут** попасть файлы двух разных модов -
на ветке модуля файлов соседа просто нет.

## Как завести временную копию под задачу

```
git -C dev\repo worktree add -b envoy-protocol ..\wt\envoy-protocol envoy
git -C dev\wt\envoy-protocol commit -m "..."
git -C dev\envoy merge envoy-protocol
git -C dev\repo worktree remove ..\wt\envoy-protocol
```

Одну и ту же ветку нельзя выписать в двух копиях сразу - git откажет, и это защита,
а не помеха.

## Ветка наследует ствол, и это нормально

Новая ветка ответвляется от `master`, поэтому в её рабочей копии оказывается всё готовое,
что на стволе уже лежит. **Удалять его нельзя.** Коммит с удалением - обычное изменение:
слитый в ствол, он унесёт эти файлы и оттуда, а «чистая» ветка окажется отложенной порчей
мастера.

Правило «на ветке модуля файлов соседа нет» относится к тому, что на ветке **добавляют
и правят**, а не к тому, что досталось от ствола. Понадобилось изменить саму раскладку -
это решение об общей истории, и принимает его пользователь, а не ветка.

## Свежий клон

Модули в работе появляются после `git worktree add` под каждую ветку.
