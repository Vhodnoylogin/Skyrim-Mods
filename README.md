# morphbench — верстак для морфов

Программа для работы с телами и именованными морфами Skyrim вне игры: прочитать меш, посмотреть
привязки вершин к костям, измерить каждый ползунок, применить набор значений и получить
изображение — не запуская ни игру, ни Blender, ни оконный редактор.

Задача, ради которой она заведена, — **сократить время между гипотезой и её проверкой**. Пока
единственным способом увидеть морф был игровой прогон, каждая догадка стоила запуска игры,
живого человека в шлеме и описания словами. Всё, что можно увидеть без игры, должно быть видно
без игры.

## Устройство: ядро без визуала, показ поверх

Программа разделена на два уровня, и граница между ними жёсткая.

**Ядро** (`morphbench\`) — объектное, техническое и **полностью лишённое визуала**. Оно не
рисует, не открывает окон, не собирает страниц и не знает слова «пиксель». Оно загружает меши
и морфы, считает, измеряет и хранит состояние. Разговаривает числами.

**Слои показа** (`presenters\`) — надстройки поверх готового ядра. Каждая берёт у ядра числа
и превращает их во что-то видимое: таблицу в консоли, машинный JSON, картинку PNG, страницу
в браузере. Ни одна из них ничего не вычисляет сама, и ядро о них не знает.

Отсюда главное правило границы: **любое действие, которое умеет интерфейс, обязано быть вызовом
метода ядра.** API здесь — это набор методов интерфейса внутри самой программы, а не веб-служба.
Повернуть камеру, включить слой, потянуть ползунок, покрасить вершины по костям — всё это методы
`MorphBench`, а кнопка будущего окна лишь зовёт их. Проверить это правило легко: если действие
нельзя выполнить из командной строки, граница проведена неверно.

Побочная выгода прямая и ради неё всё и делается: то, чем можно управлять без окон, может делать
и чат — без человека, без экрана и без игры.

## Раскладка

    morphbench\        ядро: объекты и вычисления, ни строчки про изображение
      config.py        настройки с умолчаниями; создают файл при первом запуске
      model.py         Bone, Shape, BodyModel - геометрия, веса, кости
      morphs.py        Morph, MorphSet - именованные смещения вершин
      analysis.py      разборы: пустые морфы, отставание оболочек, границы привязок
      view.py          ViewState - состояние показа ЧИСЛАМИ: камера, слои, раскраска
      api.py           MorphBench - фасад: набор методов, которым пользуются все слои
    presenters\        слои показа, каждый поверх фасада
      text.py          таблицы для консоли
      jsonout.py       машинный вывод
      raster.py        растеризатор в PNG на numpy, без Blender
      web.py           самодостаточная страница со смотрелкой
    tests\             проверки; версионируются рядом, но вне пакета
    mb.py              командная строка - такой же клиент фасада, как и всё остальное

## Откуда берётся разбор форматов

Своих разборщиков NIF и TRI здесь нет намеренно. Меш читается библиотекой **nifly** через
её же обвязку из аддона **PyNifly**, файлы морфов — модулями `tri\trifile.py` и `tri\tripfile.py`
оттуда же. Это те самые модули, которыми морфы и пишутся, поэтому второго прочтения формата,
способного разойтись с первым, не появляется.

Путь к PyNifly программа находит сама в каталоге аддонов Blender; его можно задать явно
в `morphbench.json`, который создаётся при первом запуске.

## Референс

В `dev\ref-bodyslide\` развёрнут исходный код **BodySlide and Outfit Studio**
(github.com/ousnius/BodySlide-and-Outfit-Studio, GPLv3) — эталонная реализация всего этого
хозяйства. Полезнее всего там `src\components\`: `DiffData` — хранение смещений морфа,
`Automorph` — перенос ползунка с эталонного тела на другой меш по близости вершин,
`SliderData` и `SliderSet` — описание наборов ползунков. Это **референс, а не заимствование**:
код читается, повторяется своими средствами, но не копируется — лицензии у нас разные.
