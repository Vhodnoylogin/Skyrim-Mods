# dev - ветвь разработки

Один репозиторий, **ветка на каждую разработку**. Ствол `master` не содержит файлов модов:
здесь лежат только `.gitignore` и это описание.

Каждый модуль живёт на своей ветке, постоянно выписанной в собственную рабочую копию:

| Папка | Ветка | Что это |
|---|---|---|
| `dev\repo\` | `master` | ствол, здесь физически лежит `.git` |
| `dev\envoy\` | `envoy` | Envoy Framework: мост, шина сообщений SKSE |
| `dev\envoy-voice\` | `envoy-voice` | Envoy: тестовый адаптер к голосовой службе |
| `dev\envoy-demo\` | `envoy-demo` | Envoy: тестовый слушатель, три участника разбора |
| `dev\voice\` | `voice` | голосовая служба: распознавание и синтез речи |
| `dev\mo2ailink\` | `mo2ailink` | плагин MO2 AI Link Assistant |
| `dev\wt\<задача>\` | временная | ветка под одну задачу внутри модуля |

Такая раскладка даёт главное: в один коммит **не могут** попасть файлы двух разных модов -
на ветке модуля файлов соседа просто нет.

## Как завести временную копию под задачу

```
git -C dev\repo worktree add -b envoy-protocol ..\wt\envoy-protocol envoy
git -C dev\wt\envoy-protocol commit -m "..."
git -C dev\envoy merge envoy-protocol
git -C dev\repo worktree remove ..\wt\envoy-protocol
```

Одну и ту же ветку нельзя выписать в двух копиях сразу - git откажет, и это защита,
а не помеха.

## Свежий клон

`master` почти пуст - это нормально. Модули появляются после `git worktree add` под каждую ветку.
